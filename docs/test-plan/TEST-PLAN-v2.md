# Research MCP v2: Acceptance Test Plan (v2)

- **Date:** 2026-10-19
- **Requirements:** [PRD v2](../prd/PRD-v2.md) and the newest version of each component PRD; **design:** [LLD v2](../design/LLD-v2.md); supersedes [TEST-PLAN v1](TEST-PLAN-v1.md)
- **Changes from v1:** retention is 120 days (AT-PLAT-08, AT-MIG-13); archived papers stay searchable (AT-CACHE-43, AT-CACHE-60, AT-CACHE-61). See ADR 0011.
- **Generated sections:** 4, 5, 6 and Appendix A are generated by `tools/gen_test_plan.py` from one test list, so test ids, traceability and the work-unit map cannot drift apart. Edit the generator, not the generated tables.

## 1. Purpose and how the orchestrator uses this plan

1. Every requirement in the PRD set has at least one acceptance test or owner check (section 5). Generation fails otherwise.
2. Every M0 work unit lists its acceptance tests (Appendix A). The ECC orchestrator puts those ids in the unit description; the author writes those tests first and makes them pass; the reviewer from the other model family checks them against this plan.
3. Each test carries its id in the test function's docstring as the first token (for example `"""AT-SRCH-11: ..."""`), so `pytest -k` and coverage reports can be traced back here. A test file may hold several ids.
4. Owner checks (section 6) are things only the owner can do on the Mac (Keychain prompts, real notifications, Drive) or that need real upstreams.

## 2. Test levels and environments

| Level | Runs | Network | External systems |
|---|---|---|---|
| unit | every work unit and commit (`tools/ci.sh --python-only`) | blocked | none |
| integration | every commit | blocked | fakes from `research_mcp.testing`: `httpx.MockTransport` with recorded fixtures, `FakeProvider`, `FakeClock` and fake sleeper, fake `launchctl`, fake notifier, injected resolver, temp folders for Drive |
| contract | every commit | blocked | in-memory MCP client (`mcp.shared.memory`) against `build_mcp` |
| live | opt-in (`pytest -m live`), nightly on the Mac later | allowed | real upstreams, no credentials unless the owner runs it locally |

Network blocking: `tests/conftest.py` installs a socket guard that fails any test opening a non-loopback connection unless it is marked `live`; `pyproject.toml` deselects `live` tests by default (`-m 'not live'`). Tests run with `--import-mode=importlib`; test folders have no `__init__.py`.

Secrets in tests: only `FakeProvider` with generated values; the security suite registers those values with the redactor and scans every output.

## 3. Cross-cutting tests that every milestone keeps green

| Area | Rule | Tests |
|---|---|---|
| No secret in any output | Logs, errors, tool results, UI pages, notifications and process argument lists never contain a registered secret | AT-SEC-01, 05, 06, 07, 09, 10, 13, 14, AT-HLTH-32, 34, AT-UI-04 |
| Loopback and auth | Nothing binds beyond loopback; every request is authenticated | AT-PLAT-10, 71, AT-SEC-11, 12, AT-UI-02, 03 |
| Async discipline | The event loop never blocks | AT-PLAT-75, AT-SRCH-01, ruff ASYNC rules |
| Bounded output | No result exceeds the budget | AT-PLAT-31, 63 |
| Untrusted content | Fetched text is always enveloped | AT-PLAT-33, AT-SEC-22 |
| Adapter isolation | Adapters do no I/O of their own | AT-SRC-07, conformance |
| No silent deletion | Nothing is deleted without an owner decision; MCP discards are announced; shared files survive | AT-CACHE-33, 34, 36, 48, AT-SEC-20 |
| Docs follow code | Generated inventory and test plan are current | AT-SRC-13, `tools/gen_test_plan.py` in CI |
